# Chaos Lab Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make `/lab` an experimental playground with crown-chain simulations, alternative rules and visible model disagreement.

**Architecture:** Preserve existing forecasts and evaluation tabs. Add a default Chaos Lab tab using a pure experimental engine plus scoped React UI. All observed inputs come from a historical cutoff; future simulations mutate in-memory scenarios only. No schema changes or new dependencies.

**Tech Stack:** React, TypeScript, Next.js, Vitest, SVG and CSS.

## Experiments
1. Crown multiverse: learn smoothed transitions between successive recorded winners, sample future intervals from past positive event gaps, accumulate crown time across seeded simulations. Controls: random seed, chaos mixing toward uniform transitions, selected-player future win multiplier, future field exclusion. Already accrued throne time stays intact. Cap future events per run to keep browser responsive and report cap use. Probability/rank histograms are uncalibrated scenarios; compare simulation mean-time rank against archived final outcomes.
2. Weekend rebellion: alternate historical scoring rule using Stockholm weekend time weighted from 0 to 100%. Display resulting ranks versus official cutoff ranks. This is a rule experiment, not a prediction evaluated against the official rule.
3. Model civil war: display current/form/ridge forecasts for the same cutoff, highlight rank disagreement, report unavailable regression instead of inventing a value.
4. Crown memory: observed consecutive-winner transition heatmap; counts include defenses. Only recorded winners imply observations, not unrecorded opponents.
